## 优化器目标与反馈缺口

实际decidePromotion对质量相同、Token和耗时减半的反事实报告仍拒绝，理由是训练均分未严格提高。说明它不是成本优化器；此反事实只验证策略，不是实现了减半。候选生成只见任务与第一轮训练报告的检查失败名，未看到实际系统提示词、工具定义、环境能力或file缺失的原始错误，因此无法定位环境故障；且只能追加指令，无法删除冗长基础提示词。

## 工作目录的准确根因

LightClaw Docker envDescription正确写/workspace，但createAgentRunner给AgentSession的cwd是process.cwd()；AgentSession._rebuildSystemPrompt调用coding-agent/core/system-prompt.ts的customPrompt分支，再在末尾追加宿主cwd。原始API请求同时包含两处矛盾路径。probe-policy.mjs已确定性复现。上轮直接把根因归到agent.ts的host环境分支不准确，此处更正，不改原始实验结果。

## 固定内存与可回收增量

所有探针均3个独立进程中位数，相同GC；native-empty不加载tsx，其余使用同一开发态loader。

| 导入层 | heap MiB | RSS MiB |
|---|---:|---:|
| agent-core | 12.960 | 131.375 |
| coding-narrow | 42.696 | 219.578 |
| coding-root | 42.706 | 216.156 |
| idle-cache | 6.618 | 80.547 |
| lightclaw | 43.067 | 216.188 |
| native-empty | 3.548 | 41.438 |
| pi-ai | 12.820 | 131.359 |
| queue | 6.617 | 80.578 |
| tsx-empty | 6.213 | 78.906 |

旧缓存实验扣除各进程加载前的固定heap后，空闲增量中位数为19.317→1.343MiB，减少93.05%。相对总heap约28.7%与相对增量的比例不同，不能拿后者宣传整体内存减少。基础依赖与tsx不会随频道释放。窄导入AgentSession等仍加载相近模块图，未测到heap收益，不能只改import路径就宣称瘦身。

RSS包含heap以外的内存，短程对象释放不保证RSS同比下降；本次未用堆快照/原生分配器归因全部RSS余量，不断言具体碎片或泄漏根因。Node文档：https://nodejs.org/api/process.html#processmemoryusage 。

## 案例与指标边界

原最终集都是小文件确定性转换，基线产物36/36正确，产物质量已触顶；严格失败主要来自缺file，不代表内容生成错误。原选型集正数过滤案例存在描述歧义，已单独复现澄清，撤回将其归因于模型理解失败的说法。现有训练反馈与目标不支持用这些例子证明综合推理、长期任务或成本优化；需另设有真实失败空间的任务和成本目标，避免事后换题挑结果。队列实验固定服务20ms，本来就没有改变服务时间，且保留同频道串行；测的是背压，不是调度算法加速。

本轮未修改产品源码，也未安装缺失程序来改变对照环境。所有新真实请求与原始session保存在raw/，不覆盖旧实验。

## 追加：用例歧义的最小复现

原题“将数组中严格大于0的数各乘2”没有明确要求删除其他元素，模型输出[0,4,-4,14,4]属于合理解释；评分器却只接受[4,14,4]，产生错误失败标签。
保持环境和期望不变，仅将任务澄清为“先删除所有小于或等于0的元素”：原表述产物通过0/3，澄清表述3/3。严格通过分别0/3、1/3，澄清后仍有2次工具错误。这证明任务契约与环境错误是两个独立问题；不能把澄清题目当作原候选提质。原始记录与盲测结果不修改。
