## 真实问题与修复

首次运行得分为 90%。文件任务本身执行成功，但模型在没有长期目标时调用了 `goal_progress` 和 `goal_complete`，产生 2 个工具错误。

原因不是 Agent Loop 或目标状态机损坏，而是目标工具描述中的“每轮至少调用一次”缺少前置条件。模型能看到所有工具描述，因此把它理解成普通任务也必须执行的全局规则。

修复方式是在两个目标工具的描述中明确：只有系统提示词显示存在进行中的长期目标时才能调用，普通单轮任务禁止调用。

## 结果边界

当前数据集是功能冒烟评测，只能证明基础指令遵循、工具执行、产物检查和指标采集链路可用。模型输出具有随机性，不能用一次 100% 推断所有任务都可靠。后续可增加代码修复、失败恢复、长期目标和提示词注入等用例，并重复运行计算平均值与方差。


## 2026-10-21：修复后的指标与选择目标

`AgentRunResult.inputTokens` 现在包含非缓存输入、cacheRead、cacheWrite；与 outputTokens 相加就是本次累计报告 Token。旧报告的 inputTokens 口径不同，不应直接混算。Token 数不等于货币费用；缺失价格时不能用 cost=0 推断免费。

提示词优化 CLI 支持 `--objective=quality|tokens|latency`，默认 quality 仍要求训练均分严格提高。成本目标允许均分持平，但训练/留出集均分、最低用例得分、稳定检查、工具错误和产物失败频率的原有门禁仍生效。`--min-improvement=0.05` 要求每组每次重复的目标指标至少改善5%；`--max-regression=0.05` 限制另一资源指标最多退化5%。这是一项保守的选择规则，并不是统计显著性保证。参数先于模型调用校验，schema 3 报告保存目标与阈值。

例如，在已配置提供商与隔离工作区后，使用 `--objective=tokens --min-improvement=0.05 --max-regression=0.05` 选择质量不退化且稳定节省 Token 的候选。候选生成只接收训练任务和全部训练重复，不接收留出/最终任务；反馈包含实际系统提示词、失败检查详情、工具错误文本及运行指标。常见 Key/Bearer 形态会脱敏，诊断文本有长度上限；这不是任意敏感信息的通用检测器，评测数据仍须按本地实验数据管理。诊断读取失败另记 diagnosticError，不替代任务得分。

系统提示词保留技能目录、记忆、环境、安全与目标约束。创建技能、管理事件或查询旧日志时，Agent 通过 read 读取频道 `.lightclaw-guide.md` 中完整格式和例子。普通文件任务不再携带整份教程。首次运行探测可选命令并在同一 runner 内缓存；容器外变更 PATH/安装包后应重建 runner 以刷新能力清单。

本轮真实实验与历史记录：`docs/experiments/2026-10-21-fixes/`。主对照与追加故障回归分开报告，不能将定向复测写成盲测提升。
