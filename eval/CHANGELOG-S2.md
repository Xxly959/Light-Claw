# S2 改动记录

每个开关独立关闭时从同一 facts.json 重建布局。S2 关闭全部开关仍属于 S2 的布局器，S1 基线使用题包原生布局及 S1 Runner。dev 用于选择，test 只在冻结后评测。

## i1 常驻规则

- 假设：隐藏在笔记里的长期规则无法从普通请求触发读取。
- 改动：规则先在所属范围的索引内联。关闭时遵循事实元数据的原始内联或笔记位置。
- 预期收益：提高隐式规则遵循率。
- 预期风险：常驻规则增多，可能增加 token 或与用户当前请求冲突。
- 实测结果：待 dev。

## i2 优先级与双预算

- 假设：按追加顺序截断会首先丢失尾部事实和更正。
- 改动：规则优先，其次更正、热点和路由。索引受 1,800 字符和 4,096 字节上限约束。放不下的事实转入笔记，索引显示省略数量和完整目录链接。
- 预期收益：缩小常驻内容并减少位置效应。
- 预期风险：目录层可能增加一轮读取。规则超预算时显式拒绝渲染，需要操作者整理规则。
- 实测结果：离线构造用例验证两个预算和全部事实可达，模型指标待 dev。
