# LightClaw 最终项目目标与完成边界

## 项目目标

基于pi构建单实例、自托管、同一信任域的个人Agent。主要入口是飞书；Slack保留现有适配。用户在聊天里交付任务，Agent使用文件/Shell工具执行，保存上下文、记忆、目标进度和产物；需要用户确认或恢复时给出明确状态。代码可从源码启动，也可按调用链学习。

## 最终保留的能力

| 能力 | 当前实现 | 完成条件 |
| --- | --- | --- |
| 平台接入 | FeishuBot / SlackBot / ChatTransport | 消息标准化、排队、回复和附件错误有明确路径 |
| Agent执行 | createAgentRunner + pi loop | 多轮工具调用、取消、模型失败/降级与资源上限 |
| 会话与记忆 | SessionManager / context.jsonl / MEMORY.md | 每轮刷新；历史与当前上下文有明确区别 |
| 提示词辅助 | 独立生成、约束复核、可编辑预览 | 未确认不执行；最终文本进入主上下文，说明/原文不自动注入 |
| 长期目标 | GoalStore + verifier | 进度持久化、暂停/恢复/取消、文件/命令或创建者确认 |
| 受控执行 | capability / approval / sandbox | 原始平台身份和授权检查；拒绝不扩大权限 |
| 运行恢复 | inbox / operation journal / instance lock | 排队持久化、未知结果不自动重放、人工/recover |
| 运维 | health / audit / state-backup | 状态可检查，备份校验与恢复有明确路径 |

## 不再扩展的范围

- Agent/model效果评测、数据集评分、候选晋升、性能benchmark已从产品代码移除。评测属于用户的另一个项目。
- 不增加新平台、图形控制台、自动自改系统提示词或多Agent协作。
- 不提供多租户隔离、跨机器租约、分布式高可用或任意Shell副作用的exactly-once保证。
- 不把独立安装与有限功能验证扩展为真实Slack/Docker所有场景已复验，或模型总能完成任务。

目标的文件/命令验收、提示词约束复核、运行Token预算和回归测试仍是产品保障，不能因为删除“评测”就一起删除。历史报告不抹去，但不再作为新版本当前效果证明。

当前源码实例可运行；此前用户已实际使用飞书私聊及提示词交互。2026-11-06经明确授权，隔离构建5包并独立离线安装，68个工程测试文件共667项通过（含真实Docker取消故障4项），安装产物完成独立改写/约束复核、固定回复Agent真实模型往返、私聊发送/更新和虚构文件上传。没有Agent效果实验；这不证明所有真实平台、Docker或任务场景。真实客户端已由用户完成优化预览、编辑和确认，主会话记录同时验证最终文本与原文/说明隔离，完整证据见../../../docs/reports/FINAL-ACCEPTANCE-2026-11-06.zh-CN.md。需要新环境上线时，使用deployment.zh-CN.md和下方人工功能清单核对，不能跳过平台权限或凭证检查。

## 新环境人工功能清单

这是日常功能验收，不是模型能力排行榜；涉及外发动作由操作者在自己的会话执行。

1. 本地--help不读凭证；配置后只启动一个实例；健康状态正确区分锁、进程、ready与SDK连接。
2. 在自己的私聊发送简短消息，确认回复；群里@机器人，确认没有把调用机器人的mention当任务正文。
3. 打开任务入口，分别试原文发送、优化预览、编辑确认。未确认不执行；重复点击不重复执行。
4. 共享一份非敏感小文件并请求返回结果，检查附件权限失败有明确提示，不把host任意路径直接外发。
5. 用小目标观察progress/pause/status/resume；自然语言完成等待创建者确认；不将“模型说完成”当验收通过。
6. 在可恢复的本地任务中检查stop，正常停止进程后确认锁释放；重启保留上下文与未知结果，不手删控制记录。
7. 停机后备份到全新目录、verify、恢复到另外一组全新工作/控制目录。先确认不覆盖真实目录。

学习和日常使用可以从当前源码开始；上述跨环境操作不是隐含授权助手代发消息、改权限或恢复真实数据。
